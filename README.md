# Boss 直聘自动沟通助手

> 用 **CDP（Chrome DevTools Protocol）** 驱动你自己电脑上那个**已经登录的真实 Edge 浏览器**，自动筛选岗位并批量点击「立即沟通」。
> 登录全程由本人手动完成，脚本**从不代替你登录**。

**适用平台**：Windows 10 / 11 ×64 ｜ **运行环境**：Python 3.8+ ｜ **依赖**：仅 `websocket-client`（包内已自带）｜ **不需要**：Selenium、Playwright、任何浏览器驱动

## 一、项目简介

### 它解决什么问题

求职期间需要**大量、持续、低强度**地向匹配岗位发起沟通。手动操作的问题是：重复劳动、容易漏掉好岗位、难以保持稳定节奏。

这个脚本把这件事拆成两步：

1. **扫描**（每两天一次，约 80~90 分钟）：按「关键词 × 城市」组合枚举搜索，逐个打开职位详情页核实薪资与 HR 活跃度，筛出约 110 个合格岗位存成候选池。
2. **投递**（每天 ≤50 个，建议分早/中/晚 3 批）：从候选池按「实习/应届优先 + 重点城市优先」取一批，模拟人工滚动与点击，逐个点击「立即沟通」。

### 它和别的自动化工具有什么不同

| 对比项 | 常见方案（Selenium / Playwright） | 本项目 |
|---|---|---|
| 浏览器 | 脚本自己启动一个受控浏览器 | **你日常用的真实 Edge**，独立 profile |
| 风控特征 | `navigator.webdriver = true`，容易被识别 | `false`，与人工操作无法区分 |
| 登录 | 需要填写账号密码或读 Cookie | **人工登录一次**，登录态由浏览器自己保持 |
| 输入方式 | DOM 事件注入 | **系统级合成输入**（真实鼠标移动 + 点击坐标） |
| 反爬应对 | 容易被指纹识别拦截 | 页面无法察觉自己处在自动化中 |

### 特性一览

- ✅ 拟人化节奏：真实鼠标轨迹移动、随机停顿、模拟阅读（非瞬时点击）
- ✅ 薪资精准过滤：进入详情页读取**明文薪资**（列表页薪资被自定义字体混淆，直接读会读错）
- ✅ HR 活跃度过滤：只投「今日 / 刚刚 / 昨日 / 3 日内」在线的 HR
- ✅ 实习/应届优先：先投实习与应届岗，再用普通岗补足
- ✅ 候选池复用：扫描一次用两天，大幅降低总请求量
- ✅ 静默限流自保护：连续多次无响应自动停止（可配置阈值）
- ✅ 断登录告警：检测到登录失效立即停止并报告，**绝不尝试自动登录**
- ✅ 独立 profile：完全不影响你日常使用的 Edge
- ✅ 零配置依赖：唯一的第三方库已随包内置，无需 pip 安装

### 它**不做**什么

- ❌ 不自动登录、不保存你的账号密码
- ❌ 不自动回复 HR 消息、不跟进对话（回复追踪尚未实现）
- ❌ 不上传任何数据到任何服务器（所有数据只存在你本机）
- ❌ 不保证无人值守运行（依赖人工登录与开机，详见[已知限制](#十已知限制诚实版)）

## 二、工作原理

### 整体链路

```
┌──────────────────────────────────────────────────────────────────┐
│                       你的 Windows 电脑                           │
│                                                                    │
│   ┌─────────────────┐         CDP (WebSocket)      ┌───────────┐  │
│   │  boss_batch.py   │ ◄──────────────────────────► │   Edge    │  │
│   │  daily_report.py │     127.0.0.1:9223           │ 已登录账号 │  │
│   │  cdp_health.py   │ ◄──────────────────────────► │           │  │
│   └─────────────────┘                               └─────┬─────┘  │
│           │                                                │       │
│           ▼                                                ▼       │
│   candidates.json / boss_sends.db / 日报_*.md        www.zhipin.com │
└──────────────────────────────────────────────────────────────────┘
```

**关键点**：脚本与浏览器之间只通过本机回环地址 `127.0.0.1:9223` 通信，用调试协议**控制一个真人在用的浏览器**，而不是启动一个新的受控浏览器。

### 三个脚本各干什么

| 脚本 | 职责 |
|---|---|
| `boss_batch.py` | 主流程：扫描候选池 → 批量投递 → 落库 → 生成汇总（[核心函数](#核心函数速查)见下） |
| `daily_report.py` | 从 SQLite 汇总当日投递情况，生成 `日报_YYYY-MM-DD.md`，可选推送飞书 |
| `cdp_health.py` | 链路体检（零消耗、不投递）：检查 CDP 端口 / 登录态 / 页面前台 / 合成输入是否正常 |

### 投递流程（单批次）

```
读取候选池 candidates.json
        │
        ├─ 池子过期（≥2 天）或不存在 ──► 进入扫描模式（约 80~90 分钟）
        │                                   │
        │                    关键词 × 城市逐组搜索，每组合取 2 条
        │                                   │
        │                    逐个打开详情页 → 读明文薪资 → 判 HR 活跃度
        │                                   │
        │                    合格者写入候选池（上限 110 个）
        │                                   │
        └─ 池子有效 ──► 按优先级取一批（实习/应届 → 重点城市 → 全国兜底）
                                │
                     每投一个：滚到按钮 → 检测可用 → 鼠标移动 → 点击 → 校验
                                │
                        连续 N 次无响应 ──► 判定限流，立即停止
                                │
                     写入 boss_sends.db，输出本批汇总
```

### 核心函数速查

| 函数 | 行号 | 作用 |
|---|---|---|
| `ensure_foreground()` | 72 | 把 Edge 窗口拉到前台（页面不在前台时合成输入会被系统丢弃） |
| `human_click()` | 151 | 拟人化点击：先移动到目标坐标再按下 |
| `read_salary()` | 233 | 从详情页读取明文薪资 |
| `sal_ok()` | 299 | 薪资过滤：月薪 3–8K 或日薪 ≥100 元 |
| `active_ok()` | 324 | HR 活跃度过滤：三天内在线 |
| `intern_ok()` | 358 | 实习/应届岗识别 |
| `scan_candidate()` | 425 | 扫描单个候选并判定是否合格 |
| `click_candidate()` | 458 | 投递单个候选（点击「立即沟通」） |
| `db_log_send()` | 575 | 投递结果写入 SQLite |
| `push_feishu()` | 612 | 可选：日报推送飞书 |

## 三、环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| **操作系统** | Windows 10 / 11（64 位） | 依赖 Windows 的窗口与合成输入接口，暂不支持 macOS / Linux |
| **浏览器** | Microsoft Edge（系统自带即可） | 需支持 `--remote-debugging-port`，Win10 1809 之后的版本都可以 |
| **Python** | 3.8 ~ 3.13 | **没装也没关系**，双击 `install_python.bat` 自动安装 |
| **第三方库** | 仅 `websocket-client` | **已随包内置**在 `toolchain/pylibs/`，无需 pip 安装 |
| **磁盘** | 约 30 MB | 脚本 + 内置依赖（日志与数据库会随使用增长） |
| **网络** | 能正常访问 Boss 直聘 | 无需任何代理/加速器 |
| **账号** | 一个能正常登录的 Boss 直聘账号 | 登录由本人手动完成 |
| **权限** | 普通用户权限即可 | 不需要管理员权限 |

> **关于手机端**：Boss 直聘手机端与网页端登录会互相顶掉。使用本工具期间，**请先退出手机端 App**。

## 四、安装与环境搭建（详细步骤）

> 全程约 10 分钟（首次建池另需 80~90 分钟）。按顺序做完 8 步即可。

### 步骤 0 · 获取代码

**方式 A：Git 克隆**

```bat
git clone https://github.com/ztt0608/boss-auto-apply.git
cd boss-auto-apply
```

**方式 B：直接下载**

在仓库页面点 `Code` → `Download ZIP`，解压到**任意目录**（路径里有中文也可以，但建议用纯英文路径，例如 `D:\boss-auto-apply`）。

> 💡 整个文件夹是**便携的**：没有写死盘符，放在哪都能跑，用 U 盘拷到别的电脑也行。

### 步骤 1 · 环境自检

双击 **`check_env.bat`**。

它会检查三项并给出结论（脚本输出为英文，避免 cmd 中文乱码）：

```
[1/3] Checking Python ...
    OK: 3.13.12
[2/3] Checking bundled websocket-client ...
    OK: 1.9.0
[3/3] Checking Edge ...
    OK

=== All checks passed ===
Next: run start_edge.bat, log in to Boss, then run health_check.bat
```

- 三项全 OK → 进入步骤 3（若 Python 没装，进入步骤 2）
- 提示 `[FAIL] Python not found.` → 进入步骤 2

### 步骤 2 · 安装 Python（仅在缺失时需要）

双击 **`install_python.bat`**，它会：

1. 优先尝试 `winget` 安装；
2. 若系统没有 winget，则使用**官方安装包静默安装**（设备上需能联网）；
3. **全程不需要管理员权限**（按当前用户安装）。

安装完成后**重新双击 `check_env.bat`** 确认三项变绿。

> 想手动安装也可以：到 <https://www.python.org/downloads/windows/> 下载 Python 3.12/3.13 的 Windows installer，安装时**勾选 `Add python.exe to PATH`**。

### 步骤 3 · 启动带调试口的 Edge

双击 **`start_edge.bat`**。

它做三件事：

1. 自动探测本机 Edge 的安装位置；
2. 用**独立 profile**（包内 `edge_profile\` 目录）启动 Edge，并开启调试端口 `9223`；
3. 打开 Boss 直聘首页。

**这一步的意义**：独立 profile 保证脚本控制的 Edge 与你日常使用的 Edge **完全隔离**——你自己开的 Edge 不受影响，脚本申请的登录态也不会污染你的日常浏览器。

> ⚠️ **不要**用日常的 Edge 窗口去做这件事，也不要在脚本运行时关掉这个窗口。

### 步骤 4 · 在 Edge 里登录 Boss 直聘

在弹出的 Edge 窗口里**手动登录**（扫码或密码登录均可）。

**同时退出手机端 Boss 直聘 App**（否则手机端会把网页端顶下线）。

登录一次即可，登录态保存在包内的 `edge_profile\` 里，之后启动会自动带上。

> 🔒 **脚本不会替你登录**，也不会读取或保存你的账号密码。如果哪天登录失效了，脚本只做「检测 → 报告 → 停止」三件事。

### 步骤 5 · 链路体检

双击 **`health_check.bat`**（零消耗，不投递、不访问职位）。

期望看到全部正常：

```
[1] CDP 正常：Edg/120.0.2210.91
[2] zhipin 页面：https://www.zhipin.com/web/geek/job?query=...
[3] 登录态：loginBtn=False greetBtn=True  → 已登录
[4] 前台：hasFocus=True  visibilityState=visible  hidden=False
[5] 滚动容器：...
```

**关键看两项**：`[3]` 是「已登录」、`[4]` 的 `hasFocus=True`（页面在前台）。

**退出码含义**：

| 退出码 | 对应输出 | 含义 | 处理 |
|---|---|---|---|
| `0` | 全部正常 | 一切就绪 | 继续 |
| `2` | `[1] CDP 不通` | 调试端口连不上 | 重新执行步骤 3；确认没有日常 Edge 抢占 |
| `3` | `[2] 未找到 zhipin 页面 target` | 没有打开 Boss 页面 | 重新执行步骤 3 |
| `4` | `[3] 登录态：… → 未登录` | 登录失效 | 回到步骤 4 登录 |
| `5` | `[4] 前台：hasFocus=False` | 页面不在前台 | 把 Edge 窗口切到前台、别最小化，再试一次 |

> 加上 `--try-fix` 参数可以让体检工具尝试自愈（例如自动把窗口拉回前台）：
> `python cdp_health.py --try-fix`

### 步骤 6 · 首次建立候选池

双击 **`run_batch.bat 0`**（参数 `0` = 只扫描、不投递）。

- **耗时约 80~90 分钟**，请让它安心跑完，中途不要关窗口。
- 期间脚本会大量访问职位页面，属于正常现象。
- 完成后会生成 `candidates.json`（候选池，目标约 110 个合格岗位）。

> 💡 为什么先扫不投？先确认整条链路（搜索 → 详情页 → 过滤）都正常，再动用「投递」这个有额度的动作，比较稳妥。

### 步骤 7 · 正式投递

双击 **`run_batch.bat`**（默认投 17 个，约 25~30 分钟）。

- 日志实时写入 `boss_run_latest.log`
- **日志最后一行出现 `===DONE===` 才算真正跑完**
- 投递期间请保持 Edge 窗口在前台、不要最小化、不要锁屏（原因见[故障排查](#八故障排查)）

### 步骤 8 · 查看日报

双击 **`run_report.bat`**，生成 `日报_YYYY-MM-DD.md`，内容示例：

```markdown
# Boss 投递日报 · 2026-09-17

| 指标 | 数值 |
| --- | --- |
| 今日实际发出（已沟通） | **17** |
| 其中实习/应届 | 9 |
| 已沟通/死岗（未重复发） | 3 |
| 全天目标 | 50（07/13/19 三批 17/17/16） |
| 达成率 | 34% |
| 候选池（2026-09-16） | 总 110，已点 33，待点 77 |
| 数据库累计 | 128 条 |

## 批次复盘
（按 07:00 / 13:00 / 19:00 三个批次分别汇总实际发出数量与备注）
```

配置了飞书 Webhook 的话，日报还会自动推送到飞书（可选，见[配置说明](#六配置说明)）。

## 五、日常使用与节奏控制

### 建议节奏

| 时段 | 数量 | 说明 |
|---|---|---|
| 早 | 17 | 建议 07:00–09:00 |
| 中 | 17 | 建议 13:00–14:00 |
| 晚 | 16 | 建议 19:00–20:00 |
| **合计** | **50** | 全天上限 |

**为什么是 50 个**：实测连续发送约 25~29 条后，Boss 会进入**静默限流**（不报错、但点击不再生效），次日自动恢复。把 50 个拆成 3 批、间隔 4 小时以上，可以分散请求压力。

**不要贪多**：单日超过 50 个、或同一天反复多轮，触发风控冷却的概率显著上升（严重时可达 24 小时）。

### 每天开跑前的检查清单

- [ ] 网页版 Boss 已登录（`health_check.bat` 显示「已登录」）
- [ ] 手机端 Boss App 已退出
- [ ] Edge 窗口在前台、没有被最小化
- [ ] 候选池还新鲜（`candidates.json` 距今 < 2 天；过期脚本会自动重扫）

### 手动设置定时任务（可选）

Windows 自带「任务计划程序」即可实现每天 3 批自动运行：

```
程序：  D:\boss-auto-apply\run_batch.bat
参数：  17
起始于：D:\boss-auto-apply
```

再建两个任务，分别在 13:00 与 19:00 运行，参数分别为 `17` 与 `16`。

> 前提是电脑已开机、Edge 已按步骤 3 启动并保持登录。

| 薪资过滤规则 | **299** | `sal_ok()` | 月薪 3–8K 或日薪 100–1500 元 |
| HR 活跃度过滤 | **324** | `active_ok()` | 仅「今日/刚刚/昨日/3 日内」 |

> ⚠️ **城市名必须用 Boss 官方编码**：参考 <https://www.zhipin.com/wapi/zpCommon/data/city.json>。
> 注意 Boss 网页端**不支持省份聚合码**（如「福建省」），必须一个城市一个城市地列。

### 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `BOSS_BATCH` | `TARGET` | 本批目标数量 |
| `BOSS_SCAN_AFTER` | 未设置 | 设为 `1` 时，点完本批后若候选池已 ≥2 天，自动全量重扫 |

## 八、故障排查

> 遇到问题**先双击 `health_check.bat`**，多数问题能直接定位。

| 现象 | 原因 | 处理 |
|---|---|---|
| 体检报「未找到 zhipin 页面 target」 | 调试版 Edge 没开，或被日常 Edge 抢占 | 先关掉所有 Edge 窗口，再重新双击 `start_edge.bat` |
| 脚本能读到职位，但点击毫无反应 | **页面不在前台**（最小化 / 被遮挡 / 锁屏） | 把 Edge 切到前台重跑。脚本内置自动拉前台逻辑，但保持前台最稳 |
| 连续出现「继续沟通=False」且无报错 | Boss **静默限流** | 今天到此为止，**次日自动恢复**，不要反复重试 |
| 提示登录失效 | 登录态过期，或手机端顶掉了网页端 | 在 Edge 里重新登录，并退出手机端 App（脚本绝不自动登录） |
| CDP 端口 9223 连不上 | 上面有日常 Edge 实例在跑，导致参数被吞 | 关闭日常 Edge，重新执行 `start_edge.bat` |
| 扫描到一半突然中断 | Edge 被关闭，或电脑休眠 | 重新执行步骤 3 与步骤 5，然后重跑 |
| 日志卡住不动 | 网络抖动或页面加载慢 | 等 1~2 分钟；若日志停在同一步超过 5 分钟，按 Ctrl+C 终止后重跑 |

### ⚠️ 一个最容易误判的坑

**「标签页不在前台 ⇒ 所有合成输入被静默忽略」**，表现和「被风控限流」几乎一模一样——都是"点了没反应、也不报错"。

所以遇到"点了不动"，请按这个顺序排查：

1. **页面在前台吗？**（窗口是否最小化 / 被其他窗口遮挡 / 锁屏）
2. **浏览器真的还活着吗？**（`health_check.bat` 看 CDP 与登录态）
3. **最后才怀疑风控**（连续多天无效才考虑冷却）

## 九、数据与隐私

**本项目不上传任何数据。** 所有内容只写在你本机磁盘上：

| 文件 | 内容 | 是否含隐私 |
|---|---|---|
| `candidates.json` | 候选岗位列表（职位名、公司、薪资、链接） | 不含个人身份信息 |
| `boss_sends.db` | 你的投递记录（SQLite） | 你的求职行为记录，**请勿外传** |
| `boss_run_latest.log` | 运行日志 | 可能包含职位信息 |
| `日报_YYYY-MM-DD.md` | 每日汇总 | 你的求职行为记录 |
| `edge_profile\` | **浏览器登录态（含 Cookie）** | ⚠️ **极度敏感，绝对不要外传或提交到 Git** |

### 使用建议

- `edge_profile\` 里装着你的 Boss 登录 Cookie——**等同于你的账号凭证**。不要拷贝给别人，不要上传网盘，不要提交到代码仓库（本仓库的 `.gitignore` 已默认排除）。
- 如果要换电脑，**不要拷 `edge_profile\`**，在新机器上重新登录一次即可（详见[迁移](#十二迁移到其他电脑)）。
- 想把投递记录清理干净：删除 `boss_sends.db` 与 `日报_*.md` 即可。
- 账号密码**从未**被脚本接触：登录是你在浏览器里手动完成的，脚本只是通过调试协议"借用"已经登录好的浏览器。

## 十、已知限制（诚实版）

1. **无法真正无人值守**：依赖「人工登录 + Edge 保持开启 + 电脑不休眠」，任一环节断掉都会中断。
2. **只点「立即沟通」**：使用 Boss 默认招呼语，不会自动打字、不会跟进回复；HR 回复的跟踪尚未实现。
3. **每天上限约 50 个**：这是为规避风控设置的硬约束，不是脚本性能限制。
4. **首次使用要花 80~90 分钟建池**：每台新机器都要跑一次完整扫描。
5. **依赖页面结构**：Boss 若改版（按钮文案、DOM 结构、字体混淆方案），脚本可能失效，需要同步更新选择器。
6. **仅支持 Windows**：依赖 Windows 的合成输入与窗口接口。
7. **风控风险始终存在**：即使做了拟人化与低频控制，也不能 100% 保证账号安全。

## 十二、迁移到其他电脑

整个文件夹是**便携的**：无盘符硬编码、依赖内置、Edge 路径自动探测。

1. 把整个文件夹拷到新电脑任意位置（约 0.3 MB，U 盘/网盘均可）
2. 双击 `install_python.bat`（若新电脑没装 Python）
3. 双击 `check_env.bat` 确认三项全绿
4. 双击 `start_edge.bat`，在**新 Edge 里重新登录 Boss**
5. 双击 `health_check.bat` 体检通过后，先 `run_batch.bat 0` 重建候选池

**什么能带走、什么要重来：**

| 项目 | 能否迁移 | 说明 |
|---|---|---|
| 脚本 + 内置依赖 | ✅ 直接拷 | 无需安装任何东西 |
| `boss_sends.db`（投递历史） | ✅ 可拷 | 放回根目录即可，日报能接上历史 |
| `candidates.json`（候选池） | ⚠️ 可拷但意义不大 | 岗位时效性强，建议直接重扫 |
| **`edge_profile\`（登录态）** | ❌ **绝对不要拷** | 含登录 Cookie，跨设备既容易失效又有泄露风险。新机器重新登录一次 |
| 你改过的配置 | ✅ 手动带走 | 对比新旧机器 `boss_batch.py` 改过的几行 |

## 十三、常见问题 FAQ

**Q：会不会被封号？**
A：无法保证。脚本已尽量降低风险（真实浏览器、拟人输入、低频、分散请求），但自动化行为本身可能违反平台协议。**请自行评估，从小量开始试用。**

**Q：为什么不直接用 Selenium / Playwright？**
A：因为它们启动的浏览器带有可被检测的自动化特征（`navigator.webdriver` 等）。本项目改为用调试协议控制**你日常的真实 Edge**，页面无法察觉。

**Q：需要装浏览器驱动吗？**
A：不需要。Edge 自带调试协议支持，零驱动依赖。

**Q：为什么要点「立即沟通」时必须让窗口在前台？**
A：脚本用的是**系统级合成输入**（模拟真实鼠标），操作系统只会把这类输入投递给前台窗口。窗口不在前台时，点击会被系统直接丢弃——**页面收不到，所以也不报错**。

**Q：扫一次 80 多分钟，能不能更频繁？**
A：不建议。扫描是最重的访问行为，两天一次是在"池子够用"和"请求量可控"之间的平衡点。

**Q：能自动回复 HR 吗？**
A：目前不能。这块需要处理会话状态与消息内容判断，属于后续计划。

**Q：数据会上传到你的服务器吗？**
A：不会。本项目**没有任何后端**，所有数据只在你本机。
